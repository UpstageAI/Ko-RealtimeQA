# 생성·검증 방법 (개요)

Ko-RealtimeQA 문항이 어떻게 만들어지고 검증되는지에 대한 개요다. 재현을 위한 실행 코드·프롬프트는 공개하지 않으며(벤치마크 무결성 보호), 아래는 방법 수준의 서술이다.

## 관통 원리 — 답 먼저, 질문 나중

일반적 QA 생성은 *원문 → 질문 → 답*의 순방향이라 질문에 답 단서가 새거나(정답 누설) 최신성이 없는 문항이 섞이기 쉽다. Ko-RealtimeQA는 **정답을 먼저 확정한 뒤 그 답을 묻는 질문을 만드는 역방향** 구조로 이를 앞단에서 차단한다. 핵심 규칙은 **"질문은 식별자, 답은 내용"** — 질문에는 주체·시점·명칭 같은 식별 정보만 넣고, 정답으로 이어지는 단서는 넣지 않는다.

## 파이프라인 개요

```
뉴스 원문 수집 → 제어식 역방향 생성 → 복합 자동 검증 → 선별 → 검색 동결 → 발행 → 평가
```

1. **뉴스 원문 수집** — 그 달 korea.kr 정책뉴스를 도메인별로 수집.
2. **제어식 역방향 생성** — 기사의 보도 프레임을 분류하고, 최신성 있는 사실만 골라 **정답·정답유형·질문 대상을 질문보다 먼저 확정**한 뒤, 이를 제어 조건으로 질문을 생성한다.
3. **복합 자동 검증** — 생성된 문항을 여러 독립 품질 지표로 채점하고(최신성·답변 가능성·일관성·정답 누설 여부·기사 특정성 등), 추가로 **왕복 재풀이 검증**(기사와 질문만으로 답을 다시 풀게 해 원래 답과 일치하는지 대조)을 거친다. **모든 기준을 통과한 문항만** 남긴다.
4. **선별** — 기사당 1문항으로 주제 다양성을 확보하고, 도메인 균형을 맞춰 최종 세트를 구성한다.
5. **검색 동결** — 각 문항을 실제로 웹검색해 관련 문서를 확보하고, 그 결과를 특정 시점에 동결한다. 모든 모델이 동일한 검색 스냅샷을 받아 평가가 공정·재현 가능해진다.
6. **발행** — 안정 ID 부여, 정답 분리(정답 포함본/공란본/원문/검색본), 체크섬·라이선스 정리.
7. **평가** — 동일 문항을 `closed`/`retrieved`/`oracle` 3조건으로 평가하고, LLM judge가 채점한다.

## 분류 체계

- **도메인**: 경제 · 사회 · 외교 · 문화
- **유형**: 사실형(Factoid) · 시점형(Temporal) · 인과형(Causal)

## 시간축 분리

정답을 모델 지식 cutoff 이후 발행 뉴스로 구성함으로써, 모델의 **내부(parametric) 지식**과 **외부 제공 문맥**을 시간 차원에서 분리한다. `closed`가 낮아야 문항의 최신성이 입증되고, `retrieved`는 실제 검색 활용 능력을, `oracle`은 상한선을 나타낸다.

## 공개 범위

- **공개**: 회차 데이터, 검색 동결본, 단독 실행 평가 스크립트, 주요 모델 성적, 본 방법 개요.
- **비공개**: 생성·검증 파이프라인의 실행 코드와 프롬프트. 문항의 예측·오염을 막고 벤치마크 무결성을 지키기 위함이다.
